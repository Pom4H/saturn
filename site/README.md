# Saturn SCADA — landing as the first state of the IDE

Новый сайт построен вокруг единственного экземпляра SCADA Shell. Первый экран
показывает продукт и открытый пример. На лендинге работает та же IDE, которую
кнопка «Развернуть» переводит во весь экран: редактор, модель, выбор, история и
исходник при этом не пересоздаются. Старые маркетинговые секции больше не
включены в страницу.

Основа — первая source-first IDE этого репозитория (`src/source.ts`, `src/view.ts`,
`src/view3d.ts`, `src/completion.ts`). Декларативный TypeScript остаётся единственным
источником схемы. Из Worken OS сохранён принцип одного живого экземпляра приложения.
Интерфейс строится вокруг инструментов SCADA: схема, код и свойства.
Постоянная боковая навигация, декоративные подписи и повторные CTA удалены.

## Пользовательский путь

1. Открыть `/` — новый лендинг, пример «Насосная станция» в 3D.
2. Выбрать 2D или 3D явной кнопкой. Обычная прокрутка страницы не меняет
   камеру или представление; sticky-сценария и автоматического режима нет.
3. Выбрать оборудование, изменить параметр или исходник.
4. Развернуть тот же редактор на весь экран. Выбранный вид и объект сохраняются.
5. «Создать проект» сохраняет точный текущий исходник под новым именем.
   Копия становится самостоятельным проектом; черновик примера остаётся отдельно.
6. Открывать проекты через список в верхней панели; устанавливаемое PWA восстанавливает
   активный проект и открывает Shell во весь экран.

## Реальные инструменты

- CodeMirror: TypeScript, подсветка, дополнение полей и портов из каталога,
  диагностика компилятора, сворачивание блоков, изменение ширины панели.
- Схема: параметры и состояния, drag, pan, zoom, fit, создание связей через
  выходной/входной порты, удаление объектов со связями, общая Undo/Redo.
- Каталог: резервуары, насосы, клапаны, расходомеры, теплообменники, выходы,
  манометры и термометры на выбранном трубопроводе.
- Код и свойства открываются рядом со схемой. Каталог — по кнопке «Добавить».
  На телефоне схема, код и свойства переключаются вкладками.
- Импорт .ts создаёт отдельный проект; экспорт .ts, автономный HTML и ссылка
  с исходником работают без внешнего сервиса. Копирование ссылки требует
  разрешённого clipboard API браузера.
- Ctrl/⌘ Z и Shift Z, Ctrl/⌘ S, Delete, F, Escape. Колесо масштабирует в
  полноэкранном режиме; на лендинге обычный скролл продолжает прокрутку страницы.
- Ошибка исходника сохраняет последнюю валидную схему и блокирует её изменения.
  Вычисляемые поля не заменяются литералами визуальным редактированием.

Shell поддерживает однофайловые примеры `@scada/core` и многофайловые проекты
`plant` DSL, включая авторизованное чтение серверной ревизии (подробнее ниже).
Таблица сигналов различает параметры исходника и расчёт учебной модели.
Серверная симуляция подключена через SSE; публикация правок из Shell пока не подключена. Серверное приложение
доступно по `/plant/app/`.

## Файлы

- `index.html`, `styles.css`: новый лендинг и DOM единственной оболочки.
- `studio.ts`, `studio.css`: навигация, workspace, 3D/2D, редактор,
  fullscreen, локальные проекты. При fullscreen меняется размещение Shell,
  без iframe, навигации на другой сайт или второго экземпляра редактора.
- `shell-projects.ts`: независимые черновики примеров, локальные проекты и
  валидация формата хранилища `saturn.shell.workspace.v1`.
- `exports.ts`: переносимый HTML, файлы и ссылки.
- `pwa.ts`, `manifest.json`, `sw.js`: установка и офлайн-оболочка.
- `model.ts`, `scene.ts`, `starter.ts`, `typescript-example.ts`, `connection.ts`,
  `project-context.ts`: прежние модели/примеры сохраняются как самостоятельные
  модули; новый лендинг не монтирует старую страницу.

## Запуск и проверки

```sh
npm run site:dev              # http://127.0.0.1:4190/
npm run site:build            # пересобрать после правок (watcher отсутствует)
npm run site:check
npm run site:test:browser
```

Браузерные проверки запускают отдельный preview на 4193 и Chrome (можно задать
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`). Проверяют новый лендинг, отсутствие смены вида от
скролла, сохранение 2D/3D при развороте, сохранение того же DOM при fullscreen, создание проекта из изменённого
примера, независимость копии, исходник, историю, соединения, экспорт, ссылки,
офлайн-восстановление, мобильную навигацию и работу без WebGL. Скриншоты находятся
в `test-results/site-studio/`.

`site:dev` проксирует `/plant/` на `127.0.0.1:4177`; порт runtime можно изменить
через `SATURN_PREVIEW_TARGET`. `plant:build` также собирает новый сайт в
`dist/plant/site`; сервер отдаёт его по `/`.

## PWA

После успешного precache публичные ресурсы и редактор доступны без сети.
Service worker `/saturn-sw.js` перехватывает только публичный HTML `/` и
перечисленные ресурсы `/site/assets/`. API, `/plant/`, токены, сессии и телеметрия
не кэшируются. Имена основных JS/CSS содержат хэш содержимого, поэтому новый
HTML не получает прежний JS при обновлении установленной версии.

Новый worker ожидает закрытия старых вкладок либо явного действия «Обновить
приложение» в настройках. Перед активацией Shell сохраняет локальный workspace;
серверные черновики в памяти и ошибка сохранения блокируют обновление.
Автоматического перезапуска во время работы нет. Установка требует HTTPS либо localhost и поддержки браузера.
Нативная установка на устройстве отдельно не проверена. При reduced motion
симуляция изначально на паузе; без WebGL остаётся 2D-редактор.

## Файлы проекта в компактном Shell

Кнопка «Файлы» открывает сворачиваемое дерево из реальных относительных путей.
Ctrl/⌘ B переключает дерево, Ctrl/⌘ P открывает поиск. Один клик открывает
preview-вкладку, двойной клик или изменение закрепляет её. Состояние CodeMirror,
выделение и история принадлежат документу и сохраняются при переходах. Закрытие
чистой вкладки не удаляет её документ. Изменённая вкладка остаётся закреплённой.

В списке проектов доступна «Многофайловая установка»: `plant.ts`,
`systems/pumping.ts`, `views.ts`, `README.md`. Это самостоятельный локальный
проект с относительными импортами и проверкой всем `plant/compiler.ts`.
Импорт/экспорт `.json` переносит полную карту файлов. Прежние однофайловые
проекты `.ts` и их хранилище совместимы с новой версией.

`site/documents.ts` хранит документы отдельно от вкладок. `site/plant-project.ts`
подключается лениво, использует реальный compiler и существующие 2D/3D рендереры,
находит исходные объявления для перехода «В исходник» и точечных правок числовых
литералов в `at`/`parameters`. Выражения и генерируемое оборудование не переписывает.
Ошибка модуля сохраняет последнюю успешную схему и блокирует визуальные правки.

«С сервера» (также в меню) читает существующий `GET /plant/api/project` в текущей
сессии того же origin. Войти можно через `/plant/login`; текущий API требует роль
engineer. Дерево и документы получаются из одной Git-ревизии. Это просмотр и
редактирование исходников с подключением серверной симуляции через SSE.
Показания доступны для чистой ревизии, совпадающей с исполняемой. Черновики и
неопубликованные ревизии не показывают значения от другой версии проекта.
Commit/publish из Shell пока не подключены.

«Обновить» в дереве проверяет серверную ревизию. Если есть изменения, новая
ревизия остаётся ожидающей; применение блокируется до отмены изменений или
сохранения их в отдельную локальную копию. Серверные документы остаются в памяти,
не попадают в публичный PWA cache или localStorage автоматически. «Скопировать
проект» явно создаёт независимую локальную копию. При закрытии страницы с
несохранённым серверным черновиком браузер предупреждает о потере изменений.

Панель дерева становится overlay на узком экране; на телефоне код и схема
занимают одну область. Настройки видимости дерева/кода и ширины сохраняются
отдельно от исходников в `saturn.shell.layout.v1`.

`site:test:browser` дополнительно проверяет файловый сценарий, undo между
документами, ошибки импортов, защиту черновиков от обновления и авторизованную
загрузку через настоящий изолированный Node/Git сервер. Для него создаются
временные база и bare repository; пользовательская установка не изменяется.

## Shell, команды и PWA

Одна строка приложения содержит проект, поиск команд и переключение панелей.
Файловые операции находятся в меню проекта. Инструменты схемы и 2D/3D — внутри
холста; масштаб снизу справа. Вкладки относятся только к редактору. На узком
холсте группы инструментов переносятся независимо от ширины окна.

- `commands.ts` — типизированный реестр доступных действий. Ctrl/⌘ K и
  Ctrl/⌘ Shift P открывают палитру; стрелки/Enter выполняют существующую команду.
  Заблокированные действия не предлагаются. F1 открывает справку с поиском.
- Native dialog удерживает фокус; Escape закрывает диалог без изменения Shell.
- `pwa.ts` — настройки установки, сети, offline cache, ручной проверки и
  применения обновлений. Светлая/тёмная/системная тема сохраняется отдельно от
  исходников. Холст сохраняет цветовую схему оборудования в обеих темах.
- Разрешение уведомлений запрашивается только кнопкой. Другая кнопка отправляет
  проверку через service worker. Заблокированное/недоступное разрешение показано
  явно. Серверные push-подписки в новый Shell не интегрированы; ссылка ведёт в
  существующее серверное приложение. Проверка не имитирует настоящую тревогу.
- `scripts/site-shell-check.mjs` проверяет команды, фокус, справку, темы, меню и
  мобильный интерфейс. Notification API подменён в тесте: запросов к ОС нет.

Обоснование решений и первичные источники: `docs/research/modern-shell-dx-2026-09-19.md`.

Переключение проектов использует `project-picker.ts`: отдельный popover с поиском,
группами, текущим проектом и клавиатурной навигацией. Нативный select скрыт и
остаётся адаптером существующей модели workspace. Проверки выполняют реальные
нажатия в новом интерфейсе. При ширине 666 px Shell сохраняет один ряд управления;
режим переключения целых панелей начинается при 520 px. Инспектор без выбранного
объекта недоступен, поэтому не заменяет схему пустой областью.

## Серверный навигатор

`navigator.ts` отображает переданную сервером карту путей и состояния Documents:
каталоги перед файлами, отдельные значки TS/JSON/документов, текущий файл, M и
ошибки. Стрелки, Home/End и Enter работают в дереве; фокус отделён от открытого
документа. Поиск сопоставляет полный путь без учёта регистра и показывает родителя.
Фильтр изменений, сворачивание каталогов и раскрытие пути текущего документа
работают с той же моделью. Ширина панели меняется мышью и клавиатурой.

Серверный источник показывает Git SHA, загрузку/ошибку и время проверки. Обновление
не затирает изменённые документы. Это редактор исходников: публикация и управление
оборудованием из этого Shell ещё не реализованы. Источник данных — серверная симуляция.

`node scripts/site-server-preview.mjs` поднимает отдельную проверочную установку
на localhost:4196: Node, SQLite, Git, полный исходный проект из 47 устройств,
перегруппированный по системам, контроллерам, представлениям и отчётам. Данные и
случайный пароль находятся в игнорируемой `.plant/navigator-preview/`; пароль
создаётся с правами 0600. Учётная запись — engineer. Это локальная проверочная
установка на учебной модели, а не подключённое физическое оборудование.
Ссылка `/?project=server#workspace` загружает серверную ревизию после авторизации.

Расширенный `site-server-check.mjs` создаёт две реальные Git-ревизии, проверяет
401/авторизованный GET, вложенные файлы, клавиатуру, поиск, изменения и блокировку
обновления до отмены локального черновика. Пользовательская база не используется.

## Симуляция как источник данных

`telemetry.ts` проверяет авторизованную `/plant/api/session` и подключает
`EventSource('/plant/api/stream')`. Данные не сохраняются в localStorage или cache.
`visualFrame` используется одновременно для 2D, 3D, PLC HMI и таблицы сигналов;
браузер не запускает независимую модель вместо сервера. Отображаются качество,
тревоги, пауза и номер кадра. Серверные source revision и runtime revision должны
совпадать, исходники должны быть чистыми. Отмена локальных изменений восстанавливает
применимость текущего кадра без новой компиляции серверной модели.

Ошибка SSE, offline или отсутствие кадров 18 секунд обнуляют актуальные значения
и HMI, выставляют offline. Переподключение повторно проверяет сессию; для
приостановленной симуляции сервер передаёт кадр каждые 10 секунд. Страница после
возврата из bfcache восстанавливает соединение. Данные физического оборудования
этот источник не представляет. `site-server-preview` теперь тикает автоматически.

`site-telemetry-check.mjs`: реальная авторизация и SSE, ручные серверные тики,
совпадение sequence обоих рендереров, числовые значения, pause/resume, draft/undo,
Git revision/publish, остановка и повторный запуск сервера.
