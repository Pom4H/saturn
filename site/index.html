Проекты

Локально

Проект — это модель объекта, а не файл мнемосхемы.

Оборудование, topology, сигналы и поведение остаются в обычном TypeScript. Saturn строит из этой модели разные рабочие представления, не создавая параллельный формат.

sourceplant.ts@saturn/core
01Diagram

2D / 3D · visual ↔ source · equipment · topology

02Runtime

telemetry · controls · alarms · historian · replay

03Operator HMI

live state · commands · navigation · Presentation IR

04Reports

history queries · tables · charts · A4 · schedules

05PLC targets

bindings · 320×240 projection · target providers

Source, published и applied — разные состояния.

Новая инженерная ревизия не должна незаметно стать работающей конфигурацией. Saturn показывает переход до runtime явно.

01SOURCEHEAD

Инженер редактирует обычные файлы. Git хранит историю и review.

→
02PUBLISHEDproduction

Ревизия выбрана для установки после validation / CI.

→
03APPLIEDPlant-01

Runtime работает на конкретной проверенной ревизии.

invalid published ≠ applied

Если новая ревизия невалидна, последняя рабочая конфигурация продолжает работать.

Если Saturn не знает ваше оборудование — расширьте его доменную модель.

Extension — обычный self-contained npm package с явным Saturn manifest. Installer проверяет sha512 и не запускает lifecycle scripts.

package.json@factory/equipment
{
  "name": "@factory/equipment",
  "version": "1.0.0",
  "saturn": {
    "api": 1,
    "entry": "dist/index.js",
    "capabilities": [
      "elements", "protocol",
      "datasource", "panel",
      "report", "command"
    ]
  }
}
$saturn extension add @factory/equipment
elements

Оборудование, порты, сигналы, SVG / 3D и доменная семантика.

protocol

Промышленные и vendor-specific протоколы.

datasource

Историки, БД и внешняя телеметрия.

panel

Пусконаладка, диагностика и сервисные рабочие места.

report

Отраслевые формы, расчёты и экспорт.

command

Калибровка, обслуживание и ограниченные workflow.
