# Saturn: первый полезный продукт

## Аудитория и обещание

Первая аудитория — инженер автоматизации или небольшая команда разработчиков оборудования. Задача: быстро описать установку, проверить поведение на стенде/модели, собрать операторский экран и передать его команде. Следующая близкая аудитория — лаборатории и обучение. Обещание лендинга: «От первой схемы до живой системы».

Это продуктовое предложение, основанное на текущих возможностях; интервью с клиентами и проверка спроса ещё не проводились. Позиционирование как готовой замены любой промышленной SCADA или универсального загрузчика прошивок пока не соответствует продукту.

## Три роли, два пути входа

| Роль | Среда | Первый полезный результат |
|---|---|---|
| Инженер | Собственный редактор/PWA; затем VS Code extension | Открыть рабочий шаблон, изменить параметр/экран, проверить, сохранить ревизию |
| Оператор | PWA своей установки | Увидеть достоверные данные и выполнить разрешённую команду |
| Гость (`viewer`) | PWA с правами просмотра | Открыть обзор без возможности управления |

Гостевой доступ — серверное разрешение на чтение. Публичный анонимный доступ не включается автоматически. Роль нельзя назначать переключателем в клиенте. Переключатель на лендинге показывает только предпросмотр возможностей.

## DSL и структура

Сохранить TypeScript как формат authoring: named imports, const, декларативные функции и относительные модули. Предметные функции `simulation`, `control`, `signal`, `view`, `plc`, `pipe` дают читаемый язык без нового синтаксиса. Новые DSL-возможности должны одновременно иметь типы, валидацию и source mapping для визуального редактирования.

Начальный шаблон состоит из `plant.ts` (состав), `equipment.ts` (оборудование/команды), `views.ts` (пульт). По мере роста проект разделяется на подсистемы и добавляет `controllers/*.ts`, `wiring.ts`, `alarms.ts`, `reports.ts`. Это соглашение для шаблонов; компилятор не должен требовать все папки для маленького проекта.

`plant.ts` остаётся точкой входа. Версия DSL/schema и target metadata должны появиться в явном манифесте при расширении формата. URL, credentials и назначения серверов — настройки среды, не исходники модели. Измерения и архив — runtime storage. Layout редактора — пользовательские настройки. Build artifacts содержат ссылку на source revision и целевую платформу.

Текущий DSL — ограниченный интерпретатор AST: произвольные функции, циклы, import из сети/диска не выполняются. На лендинге это объясняется в раскрываемом блоке, а пример проверяется настоящим compiler в `site:check`.

## Deploy как три самостоятельных артефакта

1. **Проект на сервере.** Проверенная ревизия исходников → candidate → publish → applied status. Откат сохраняет историю. Эти механизмы уже есть; следующий продуктовый шаг — компактный мастер с понятной целью и результатом проверки.
2. **Программа/прошивка контроллера.** Сейчас доступен экспорт программы `.fbdbin` для поддержанного FBD runtime. Полный образ платы потребует явного board profile, bootloader/HAL, транспорта загрузки, проверки совместимости и подтверждения результата с устройства. Нельзя называть генерацию файла успешной прошивкой.
3. **Операторское приложение.** PWA с заданными экранами и разрешениями на origin установки. Первая версия использует существующий серверный PWA. Универсальный устанавливаемый клиент с каталогом серверов требует отдельной модели authentication/CORS, ресурсов и offline state. Launcher лендинга пока сохраняет адрес и открывает сервер.

Единый CLI/набор VS Code-команд в дальнейшем должен вызывать общие application services (`validate`, `build`, `publish`, `target upload`), а не иметь отдельный deploy engine. Имена будущих CLI-команд и one-click deployment не рекламируются как уже работающие.

## Что сделано первым

Лендинг с интерактивным 3D-контуром; независимая фиксированная модель управляет визуализацией и операторским preview. Есть вход в настоящую демо, просмотр и загрузка компилируемого starter, выбор сервера, разделение ролей, объяснение публикации/PWA/контроллера. Статус расширения VS Code явно указан. До публичной публикации extension ID кнопка установки не появляется.

Следующий критерий готовности продукта — человек без знания репозитория проходит весь путь: скачать/открыть шаблон → изменить установку → проверить → опубликовать на своём сервере → войти оператором с другого устройства. Для VS Code критерий дополнительно включает установку реального VSIX и одну общую source-preserving операцию в кодовом и визуальном редакторах.
